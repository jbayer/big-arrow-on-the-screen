# Cue cards (2026-10-26)

The arrow shows the human **where**. A cue card holds **what**: the values, secrets and questions of
a step, in a floating window the human can copy from and answer. Part of bigarrow, not a sister
project: arrow and card combine both ways in one process with one lifetime (Franz, 2026-10-26:
"make it part of big arrow", "no separate repo"). Tickets T52 to T57 (M8).

## Why

An agent that needs the human to log in, paste a token, enter a 2FA code or pick an option could
only print it into a terminal the human is not looking at, or put one `{{value}}` on an arrow's
sign. Most hand-offs need more: two or three values, a secret that must not land in a log, an
answer the agent can act on.

The shared shape: rows of values, optional targets per row, actions, a lifetime, a reply.

## Commands

```bash
bigarrow card [card.json | - | flags]   # detached: prints {"pid","card","controls"}
bigarrow card ... --wait                # stays, prints the reply
bigarrow wait [pid] [--timeout s]       # the reply of a detached card (newest of this session)
bigarrow card - --update <pid>          # replace the rows of a running card
bigarrow card ... --png out.png         # offscreen; --dry-run prints the card, secrets hidden
bigarrow start --element X --text "..." --card card.json   # arrow and card as one
```

Flags for the common case: `--title`, `--note`, `--field Label=value`, `--secret Label=source`,
`--code`, `--link [Label=]url`, `--ask`, `--choice id=Label`, `--button id=Label`, `--app`,
`--color`, `--theme`, `--say`. Exit codes: 0 answered, 1 closed without an answer, 2 bad
input, 3 a target or secret source gave nothing.

## The card format

`title` (required), `rows` (required), `app`, `color`, `duration`, `theme`, `say`. Rows by `type`:
`text`, `field`, `code`, `link`, `totp`, `qr`, `image`, `file`, `choice`, `input`, `checklist`,
`progress`, `actions`. A row or checklist item may carry `point` (`element`, `rect`, `at` or
`window`, plus `app`, `role`, `anchor`, `text`): the same targets as `bigarrow point`, planned by
the same code. Unknown keys are bad input, so a typo never silently drops a row.

The reply (one JSON line): `result` (button, choice, input, checklist; closed, timeout, stopped,
ownerGone, displayGone), `value`, `inputs`, `checked`, `copied` (row labels), `opened`, `after`,
`at`. It never contains a secret.

## Decisions

- **Secrets never on argv.** `ps` shows every process's arguments to every user. Sources: `pass:`,
  `keychain:<service>/<account>`, `op:`, `env:`, `file:`, or the JSON card on stdin. The parent
  reads them (failing early with exit 3) and hands the resolved card to the detached child through
  a pipe on its stdin. Error messages never echo what was given where a source belongs.
- **Clipboard.** Copied secrets carry `org.nspasteboard.ConcealedType` and `TransientType`
  (http://nspasteboard.org); a detached `clipboard-guard` clears them after 30 s if the clipboard
  still holds them, also when the card has ended.
- **Screen capture.** `sharingType = .none` only for cards with a secret: on macOS 27
  `screencapture` leaves such a card out (checked on the test Mac). Other cards stay visible, so
  screenshots, demos and the behaviour checks can see them.
- **Focus.** A borderless `.nonactivatingPanel` at `.floating` level, never `NSApplication.run()`.
  Buttons take the first click; the panel becomes key only for a question row, and typing into it
  leaves the human's app frontmost (checked).
- **Placement.** Beside the card's `app` window when given (right, left, inside its top right),
  else the display's bottom right: macOS shows notification banners top right, over every window,
  and one covered the card's X on the test Mac. Never over the shown arrow's sign or target when a
  candidate can avoid them.
- **One arrow at a time.** The base arrow of `point --card`, or the active row's. A click on the
  arrow's sign hides the arrow; the card stays. The arrow also goes after `--duration` and when the
  agent exits.
- **Only the X, or the agent on purpose, closes a card (0.5.1, Franz: "only a click on x dismisses
  the cue card", "but the ai can also close the card").** No time limit; the prompt hook, `stop`,
  `stop --all` and the agent exiting leave it; `stop --pid <pid>` and `stop --cards` close it.
- **Questions close the card (Franz: "if there is just one question then the app closes without
  the x, if there are multiple actions all must be done before it vanishes, can be turned off").**
  Each answer row (buttons, choice, text field, checklist) counts once; the card closes 0.7 s after
  the last one, the pick lit. `keep` keeps it, with a "Sent" banner, until the X. The reply goes out
  when the last question is answered; `answers` has every answer by row. A card without questions
  stays until the X. In 0.5.0 the `UserPromptSubmit` hook closed a card the
  moment the human typed a reply to the agent, 38 s after it appeared.
- **Header.** The arrow sign's own font (SF Pro Rounded Heavy, the small sign's 30 pt), centred,
  with as much room left of it as the X takes on the right; the card's border in the sign's
  contrast colour.
- **AppKit views, not layers.** The arrow is Core Animation layers; the card is interactive, so it
  is NSViews (stack views, text fields, buttons) rendered offscreen for `--png` with
  `cacheDisplay`.

## Verification

- Unit: format, validation, redaction, reply, TOTP against RFC 6238, secret sources against the
  real environment, files and login keychain, placement, icons.
- CLI: flags, dry run, literal secret refused, empty source exit 3, unknown keys, `--png`.
- On screen (`scripts/card-check.sh`, test Mac and `visual.yml`): focus, visibility in screenshots,
  copy, buttons, X, typing, choice, secrets (argv, registry, screenshot, concealed clipboard,
  30 s clear, reply), the card staying after an answer and closing only by its X or `stop
  --pid`/`--cards`, `start --card` (its `--duration` ending only the arrow), row arrows, update.
